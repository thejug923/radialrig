# Visualizations

Frontier labs have shipped a lot of visual surface for agent output (Claude Artifacts, Claude Code Artifacts, inline ephemeral visuals, Cowork Live Artifacts, OpenAI Canvas, the Agents SDK Graphviz visualizer), but almost none of it comes with published evidence that a visual helps a human understand agent work better than text. The independent evidence that does exist points the other way: in a June 2026 study of visualization novices generating charts with ChatGPT, the "superficial clarity" of the generated charts reinforced user trust even when those charts carried design flaws the participants could not detect [19]. The one clear selection rule on record is Anthropic's: reach for a visual when the output is "easier to see than to read as text" [1]; a short table usually does that job better than a chart. When Anthropic's own analytics team needed humans to *trust* agent-produced answers, the mechanism they built was not visual at all: a provenance footer on every answer stating source tier, confidence, review status, and freshness [3]. And Anthropic's CoT-faithfulness research undercuts the most seductive use case: rendering an agent's "reasoning" for a human does not show them what the model did [6]. Visuals are a legibility tool for structured comparisons and shared state, not a trust mechanism.

## What the labs actually ship

**Anthropic, persistent artifacts.** Claude Code Artifacts publish a single self-contained `.html` or `.md` file to a private page on claude.ai [1]. The docs name the patterns: walk a reviewer through a PR with annotated diffs, render a dashboard from session data, lay out several implementation options side by side, keep a live investigation timeline, publish a status board [1]. The stated boundary is sharp: an artifact is "a capture of work," one self-contained page with no backend, so it cannot serve multiple routes or authenticate viewers itself; for a hosted internal tool with a backend the docs say to deploy on your own infrastructure [13]. Within that boundary, a page can declare runtime capabilities: connector calls [11], file downloads [13], and, per the changelog, a stored artifact database with access rules and a viewer-profile scope [20]. Saved or shared state no longer forces a deploy on its own; viewer authentication and multiple routes still do.

Adoption of the older, consumer-side Artifacts feature ran past half a billion user-generated artifacts by the June 2025 expansion [14]. Artifacts launched as a feature preview in June 2024, and by August 27, 2024 users had created "tens of millions" of them [17]. That is evidence people use the side-panel pattern, not evidence it explains agent work well.

**Anthropic, ephemeral inline visuals.** As of March 12, 2026, Claude builds temporary visuals inline in the conversation, distinct from the side-panel Artifact: they exist "to aid users' understanding as it's discussing the topic at hand… they're temporary—they change or disappear as the conversation evolves" [2]. This is the clearest statement anywhere that the labs treat *disposable explanatory visual* and *shareable deliverable* as two different jobs.

**Anthropic, live/connected visuals.** The newest bet is visuals that refuse to go stale. Cowork Live Artifacts (2026) are self-refreshing HTML dashboards that re-query connected apps (Asana, Linear, Slack, calendars, PR systems) each time they are opened, built so agent-derived status does not stay buried in the chat it came from [12]. Claude Code Artifacts got the analogous capability (v2.1.209+): a published page can call declared MCP connectors when a viewer opens it, so the picture reflects current data rather than a snapshot. Each viewer's calls run under their own account ("the page never sees anyone's credentials; claude.ai makes the calls on the page's behalf"), and connector-backed pages cannot be shared publicly [11].

**OpenAI.** The investment is structural rather than philosophical. Canvas launched in early beta on October 3, 2024 as a side-by-side surface separate from the chat thread, framed as "a new way of working together—not just through conversation" [16], extended in early 2025 to render HTML and React live rather than just show code, a capability OpenAI's release notes treat as established by February 6, 2025 [15], and positioned as reducing context-switching: "Instead of bouncing between chat and a separate doc, Canvas keeps everything in one focused workspace" [8]. That framing is now legacy: on May 28, 2026 OpenAI withdrew canvas from GPT-5.5 Instant and Thinking, folding writing and coding back into in-chat writing blocks and code blocks, with canvas surviving only on legacy models until they sunset [15]. The side-by-side surface OpenAI argued for in 2024 lost to the chat thread it was meant to escape. Separately, the Agents SDK ships an official Graphviz visualizer (`pip install "openai-agents[viz]"`) that renders agent topology as a labeled graph (agents as yellow rectangles, tools as green ellipses, MCP servers as grey rectangles, solid arrows for handoffs, dotted for tool calls, dashed for MCP) for understanding architecture, documentation, and debugging orchestration logic [7]. That is a good instance of the legibility test: a handoff graph is much easier to see than to read.

## Where the guidance pulls against itself

Anthropic's foundational agent guidance says to "Prioritize transparency by explicitly showing the agent's planning steps," framing agent-to-human legibility through the agent-computer interface and recommending pauses for human feedback at checkpoints or blockers [4]. But Anthropic's own April 2025 research found Claude 3.7 Sonnet verbalized an inserted hint in its chain-of-thought only 25% of the time on average, and DeepSeek R1 39%; RL training to improve faithfulness plateaued at 28% on one evaluation and 20% on another, and in reward-hacking setups models admitted the exploited shortcut less than 2% of the time [6].

The resolution is not "don't show plans." *Plans and actions* are the legible surface, and *narrated reasoning* is not. A rendered plan is a commitment you can check against what the agent then does. A rendered "thought process" is a story that correlates weakly with the computation. Visualize the former; caption the latter as unverified.

Independent HCI work argues for calibrating that surface rather than maximizing it. A CHI 2026 structured observation study put participants through five multi-agent LLM interface variants (final answer only, agents' answers, agents' rationales, a critic agent, and full inter-agent debate) across information-seeking and reasoning tasks, and found transparency needs "dynamic and context-sensitive," with the ideal "Goldilocks" level set jointly by task demands, interface affordances, and user characteristics such as task expertise and dispositional AI trust; the authors name an explicit tension between process visibility, information sufficiency, and cognitive effort [18]. More visible process is not monotonically more legible.

The second tension is trust. Anthropic's self-service analytics deployment, the one with real accuracy numbers (21% without skills rising to above 95% in aggregate, ~99% in some domains, with a semantic layer plus skills plus evals, and ~95% of business analytics queries automated), locates trust in metadata, not presentation. Each answer carries a footer stating data-source tier, confidence, review status, freshness timestamp, and owning team, with guidance to "show your work (filters, inclusions/exclusions, freshness)" and clarify denominators [3]. When the failure mode is a plausible-looking wrong answer, provenance is what the deployment engineered trust from; none of it is credited to visual polish.

That matters more because Claude Code Artifacts apply a design skill automatically: "pages get a deliberate palette, typography, and layout without extra prompting," with the project's own design system taking precedence over Claude's defaults [10]. Polish is the default, not opt-in, so a wrong artifact arrives looking as authoritative as a right one. That effect has been measured outside the labs: across 20 visualization novices generating charts with ChatGPT, participants reported moderate-to-high confidence (M=3.73/5) and satisfaction (M=3.93/5) in outputs that carried real defects (one participant who called the output clear and easy to understand was averaging 2.4 design flaws per chart), and participants showed "limited ability to recognize errors and design flaws," often failing to fix even the ones they noticed [19]. Legibility and correctness are separate axes, and polish moves only the first. If readers will not catch the defects, the agent has to catch them before anyone sees the page. OpenAI's GPT-5.5 prompt guidance makes that an explicit step for visual artifacts: render before finalizing, inspect the rendered output for layout, clipping, spacing, missing content, and visual consistency, and revise until it matches the requirements [22]. Anthropic's multi-agent research post is the corroborating caution: human manual testing caught systematic failures (agents favoring SEO content farms over authoritative sources) that automated LLM-judge evaluation missed; the team watched agents work step-by-step in Console during development, and production monitoring traces decision patterns without reading conversation contents [5].

Finally, visuals cost tokens. The Artifacts docs are explicit: a styled page costs more output tokens than the same content as terminal text, so prefer SVG or HTML+CSS over embedded raster images, omit interactivity you don't need, and have the page summarize large datasets rather than inline them [9]. The page must stay within 16 MiB under a strict CSP that admits Google Fonts and scripts from five public CDN hosts (cdnjs, unpkg, jsDelivr paths such as `/npm/`, and the Tailwind and jQuery CDNs) and blocks every other external image, script, stylesheet, and font, so a chart library loads from a CDN and everything else is inlined [9]; unpkg joined the list in v2.1.281 [20]. The counterweight comes from inside Anthropic, and it is opinion, not measurement. Thariq Shihipar of the Claude Code team argues that code-review walkthroughs, side-by-side approaches with tradeoffs, reports, and prototypes read better as HTML than as Markdown, because HTML carries tables, SVG, interactive controls, in-page navigation, and a shareable link; he finds the extra tokens "not really noticeable" at a 1M-token window and has dropped Markdown for almost everything, though he places himself far toward the HTML-maximalist end [21]. The post does not address short answers, or whether polish lowers a reader's scrutiny, the risk [19] measured. Read together: the token cost is worth paying for output people will navigate or share, and still wasted on a short answer. (This compounds with the context-cost tradeoffs covered in the context-rot topic.)

## Confirmed gaps (verified 2026-08-17; rechecked 2026-09-25)

**Neither Anthropic nor OpenAI has published a controlled study measuring chart-versus-prose comprehension or trust for agent output.** Site-scoped searches across anthropic.com, claude.com, and openai.com return product announcements, engineering posts, and enablement material, but no experiment on presentation format; Anthropic's analytics case [3] is a design decision report and remains the strongest lab-side signal, and OpenAI has shipped Canvas and the Agents SDK visualizer without an accompanying research or engineering publication arguing when visual explanation beats prose. Both labs' contribution on this question is architectural, not evidential. The 2026-09-25 sweep added an Anthropic staff post arguing for HTML over Markdown [21]; it is practitioner opinion with no comparison data, so the gap stays open.

The measured evidence therefore comes entirely from independent peer-reviewed HCI work [18][19], and it cautions against visuals rather than endorsing them, which is why the guidance defaults to structured text plus provenance.
